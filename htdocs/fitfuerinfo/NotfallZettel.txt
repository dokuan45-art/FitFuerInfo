# Projektübergabe – FitFürInfo

## 1. Projekt

Ich entwickle im Rahmen meiner Ausbildung zum **Fachinformatiker für Systemintegration** ein Schulprojekt für **LF12 – Kundenspezifische Systemintegration durchführen**.

Das Projekt basiert auf einem Fallbeispiel von **FitFürInfo**.

Ziel ist eine lokale Webanwendung zur Verwaltung von:

* Mitarbeitern
* Kursen
* Räumen
* Software in Räumen
* Raum-Berechtigungen
* Raumbelegungen / Buchungen
* Kalender

Die Anwendung läuft lokal mit **XAMPP** und einer **MySQL-Datenbank über phpMyAdmin**.

Die Spaltennamen müssen exakt so geschrieben werden.

# 9. Datenbankverbindung

Datei:

`config/database.php`

Aktueller Aufbau:

```php
<?php

$host = "localhost";
$dbname = "fitfuerinfo";
$username = "root";
$password = "";

try {

    $pdo = new PDO(
        "mysql:host=" . $host . ";dbname=" . $dbname . ";charset=utf8mb4",
        $username,
        $password
    );

    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
    $pdo->setAttribute(PDO::ATTR_DEFAULT_FETCH_MODE, PDO::FETCH_ASSOC);

} catch (PDOException $e) {

    die("Datenbankverbindung fehlgeschlagen: " . $e->getMessage());

}

?>
```

# 10. Login

`login.php` verwendet:

```php
password_verify($passwort, $mitarbeiter["passwort"])
```

Die Datenbankabfrage sucht nur aktive Mitarbeiter:

```sql
SELECT *
FROM mitarbeiter
WHERE benutzername = :benutzername
AND aktiv = 1
LIMIT 1
```

Nach erfolgreichem Login wird die Session gesetzt:

* `user_id`
* `benutzername`
* `vorname`
* `nachname`
* `ist_admin`

Zusätzlich wird:

```php
session_regenerate_id(true);
```

verwendet.

Der Login soll keinen Root-/Sonderlogin über den MySQL-Root-Benutzer mehr verwenden.

# 12. Aktivierungscode

Die Idee ist:

Beim Erstellen eines Mitarbeiters wird ein zufälliger Aktivierungscode erzeugt.

Dieser wird beim Mitarbeiter gespeichert.

Der Mitarbeiter kann anschließend `passwort_setzen.php` aufrufen und den Code manuell eingeben.

Nach erfolgreichem Setzen des Passworts:

```sql
aktiv = 1
aktivierungscode = NULL
```

Damit ist der Aktivierungscode nur einmal verwendbar.

Wichtig für PHP 5.6:

`random_bytes()` nicht verwenden.

Für PHP 5.6 soll z.B. `openssl_random_pseudo_bytes()` verwendet werden.

Beispiel:

```php
$aktivierungscode = bin2hex(openssl_random_pseudo_bytes(32));
```

# 13. passwort_setzen.php

Diese Seite funktioniert grundsätzlich bereits.

Der Benutzer gibt den Aktivierungscode manuell ein.

Das Formular enthält:

* Aktivierungscode
* Neues Passwort
* Passwort wiederholen

Der Aktivierungscode wird in der Datenbank gesucht:

```sql
SELECT *
FROM mitarbeiter
WHERE aktivierungscode = :aktivierungscode
AND aktiv = 0
LIMIT 1
```

Beim Speichern des Passworts:

```php
$passwort_hash = password_hash($passwort, PASSWORD_DEFAULT);
```

Danach:

```sql
UPDATE mitarbeiter
SET passwort = :passwort,
    aktiv = 1,
    aktivierungscode = NULL
WHERE user_id = :user_id
```

Wichtig: Die ID-Spalte heißt `user_id`, NICHT `id`.

Das war bereits ein Fehler, der behoben wurde.

# 16. Raumbuchungssystem

Das ist jetzt der nächste große Entwicklungsschritt.

Ein Mitarbeiter soll:

1. einen Kurs auswählen
2. einen Raum auswählen
3. Datum auswählen
4. Beginn auswählen
5. Ende auswählen

Das System prüft automatisch:

### Raumkapazität

Beispiel:

Kurs:

`25 Teilnehmer`

Raum:

`20 Arbeitsplätze`

→ Buchung nicht erlaubt.

---

### Softwareanforderungen

Ein Kurs soll später Anforderungen an Software haben können.

Das System muss prüfen:

```text
Kurs benötigt Software X
        ↓
Raum besitzt Software X?
        ↓
Ja → möglich
Nein → Buchung nicht möglich
```

---

### Zeitüberschneidungen

Ein Raum darf nicht doppelt zur gleichen Zeit gebucht werden.

Beispiel:

Raum 101:

10:00–12:00 belegt

Neue Buchung:

11:00–13:00

→ nicht erlaubt.

Neue Buchung:

12:00–14:00

→ möglich, weil der erste Zeitraum beendet ist.

---

# 17. Stornierung

Eine Buchung darf gelöscht werden von:

* dem Mitarbeiter, der die Buchung erstellt hat
* dem Administrator

Nach dem Löschen der Buchung ist der Zeitraum automatisch wieder frei.

Es muss keine zusätzliche "Freigabe" gespeichert werden.

---

# 18. Kalender

Es soll einen Kalender geben, in dem die Raumbelegungen sichtbar sind.

Der Benutzer soll erkennen können:

* welcher Raum
* welcher Kurs
* wann belegt

Eine stornierte Buchung darf nicht mehr als Belegung erscheinen.

---

# 19. Rechte

Es muss überall serverseitig geprüft werden.

Nicht nur Buttons verstecken!

Beispiel:

Ein normaler Mitarbeiter ruft direkt auf:

`admin/mitarbeiter_erstellen.php`

auf.

→ Zugriff muss verweigert werden.

Ebenso bei:

* fremde Kurse bearbeiten
* fremde Kurse löschen
* Räume ohne Berechtigung bearbeiten
* fremde Buchungen löschen

# 20. SQL-Sicherheit

SQL-Abfragen sollen über PDO Prepared Statements laufen.

Beispiel:

```php
$stmt = $pdo->prepare($sql);

$stmt->execute(array(
    ":benutzername" => $benutzername
));
```

Keine Benutzereingaben direkt in SQL-Strings einsetzen.

Ausgaben aus Benutzereingaben mit:

```php
htmlspecialchars()
```

absichern.
